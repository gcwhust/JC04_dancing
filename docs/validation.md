# 物理播放验证

平台为 Python 3.10.22 / MuJoCo 3.3.7，物理步长 **0.0005 秒**。十个关节由
`tau = clip(kp*(target-q)-kd*qvel, -max_torque, max_torque)` 驱动。
目标在每个物理步开始按 `data.time` 采样，随后执行 `mj_step`。
仅 `reset()` 使用 `standing` keyframe 初始化 qpos；播放期间不写 qpos，
不关闭重力。驱动轮由独立角位置约束锁止，未增加轮子 motor。30 FPS 的绝对
请求时间不会逐帧累计取整误差。

`check` 默认检查完整时长，输出 JSON；数值警告、非有限状态或 MuJoCo
自动重置作为错误退出。`fallen` 使用基座高度低于 0.35 m 或倾角超过
45°作为明显跌倒提示，不等于完整视觉验收。跟踪误差只作诊断，不设置验收阈值。

```bash
conda run -n jc04_dancing python -m jc04_dancing list
conda run -n jc04_dancing python -m jc04_dancing check --dance new_year --mode free
conda run -n jc04_dancing python -m jc04_dancing check --dance doudoulong --mode free
conda run -n jc04_dancing python -m jc04_dancing play --dance new_year --mode free
```

## 原动作与模型限位的冲突

严格验证首先发现新年舞蹈在完整时间轴 `t=7.876 s` 的右肩 roll 为
`−0.000128825941 rad`，超出源 URDF 的 `[0, 3.14]`。
核对原 CSV 的命名列、度/弧度转换及 URDF 同名关节后，确认不是左右、符号
或单位映射问题。新年与豆豆龙的肩 roll 经三次插值后在零附近有少量下冲；
豆豆龙原 CSV 还包含120°肘角，超出源肘关节上限。没有裁剪 CSV、改变插值或改编动作。

初次按0.002秒网格检查全时间轴，相关极值如下；当前运行还会按0.0005秒网格
重新严格验证所有原目标。这不是连续曲线极值的解析求解。

| 原曲目 | 右/左肩 roll 最小值（rad） | 右/左肘最大值（rad） |
|---|---|---|
| new_year | −0.000949889 / −0.000956534 | 小于源上限 1.85 |
| doudoulong | −0.001204854 / −0.001204854 | 2.094737610 / 2.094454086 |

`robot.yaml.model.joint_range_overrides` 明确扩大**仿真播放**范围，编译后的
运行时模型使用以下值；源 URDF 保留原字节，包内 XML仍保留这些原关节限位。

| 关节（双侧相同） | 源范围（rad） | 运行时范围（rad） | 相对源范围扩大 |
|---|---|---|---|
| shoulder_roll | [0, 3.14] | [−0.18, 3.14] | 下界 −0.18 rad（约10.313°） |
| elbow_pitch | [−1.5708, 1.85] | [−1.5708, 2.10] | 上界 +0.25 rad（约14.324°） |

在这两支舞蹈的上述采样结果中，最接近肩 roll 新增下界的是豆豆龙双肩，
余量约 0.17879515 rad；最接近肘 pitch 新增上界的是豆豆龙右肘，余量约
0.00526239 rad。两支动作所有原目标均再次经过修改后
范围验证。每次 JSON 结果记录源/运行范围，不能把这些值解释为已验证真机 ROM。
身体自碰撞未启用等模型近似继续见 [model-conversion.md](model-conversion.md)。

## 支撑、轮子制动与镜头

`free` 禁用 `base_support` weld；`supported` 显式启用该 weld，固定参考位姿
与准备 keyframe 一致。支撑模式的日志、统计及截图均标明 `supported`，不能
当作自由站立结果。

**默认为 `free` + `wheels.mode: locked`。** 两条 wheel joint equality
约束轮子相对腿部的角位置，
不焊接浮动机身、不关闭重力、不改写位置。它们是理想机械制动近似，软约束有
很小残差，未辨识真机抱闸力矩。显式 `wheel_mode='passive'` 仅供调试；摘要
记录 wheel_mode与全程最大轮角偏移/轮速，不把轮子锁止说成世界坐标完全冻结。

镜头保持 `camera.follow_base_xy: true`，只跟随实际基座的水平位置，保留固定
高度、方位和距离；没有把机器人平移回原点。`scene.floor_half_size: 50` 只扩大
无限碰撞平面的显示范围。地面棋盘固定在世界坐标，便于观察残余微动。

## 步长验证

2毫秒步长的对照运行虽保持状态有限，却出现手臂逐步正负饱和振荡。保持
KP/KD、力矩上限及原动作，只将步长改为0.0005秒，可把被动轮配置的完整
新年舞蹈最大水平位移从11.9816米降至0.038831米，且没有臂部力矩饱和。
当前配置在此基础上增加轮子锁止约束。逐步对照与积分器分析见
[control-diagnosis.md](control-diagnosis.md)。

- 轮子最大角偏移 `1.847837e-6 rad`（约0.000106°），最大角速度
  `1.165794e-4 rad/s`（约0.00668°/s）。这是锁止约束的实测残差，不是严格数学零。
- 基座世界坐标从 `(0,0,0.535930)` 到 `(0.025145,-0.001539,0.522199) m`，
  最大水平位移 **0.033393 m**；保留接触沉降和轻微姿态调整，没有冻结机身。

- 全程十关节最大控制力矩18.8274 N·m，六个臂关节力矩饱和比例均为0。
  相邻步力矩换向比例最高0.0348%，不再出现每步反转的限幅振荡。
- 准备后2秒起连续计算轮/辅助轮接触点的水平相对速度，最大0.002660 m/s。
  软接触有毫米/秒量级微滑，没有明显滑移或持续远离起点。
